# 二游日历 APP 设计文档

日期：2026-07-29
状态：已确认（用户全权委托技术决策）

## 1. 背景与目标

用户同时玩多款二次元手游，各游戏版本更新、卡池轮换、活动时间分散在不同社区，每天需要翻多个平台才能确认"今天哪个游戏更新了什么"。

**目标**：一个 Android APP（Flutter），打开即见"今日各游戏更新聚合"，数据实时从国内官方渠道抓取，无需手动维护。

**约束**：单人使用、不对外发布 → 不做账号/限流/分发兼容，一切从简。

## 2. 已确认需求决策

| 决策点 | 结论 |
|---|---|
| 数据获取 | APP 内直接抓取官方源，无后端 |
| 游戏范围 | 米哈游系（原神/崩铁/绝区零/崩3）、鹰角（明日方舟）、库洛（鸣潮/战双）、Nikke国服、阴阳师、异环（占位） |
| 游戏筛选 | 设置页勾选，仅勾中游戏进入日历 |
| 首屏 | 日历 + 当日更新列表结合 |
| 通知 | 不需要推送；需要本地缓存 |
| 详情页 | 每游戏沉浸式独立主题；公告/卡池/活动 Tab；卡池展示 UP 角色立绘，抓不到兜底看板娘；支持原文链接跳转 |
| 打包 | flutter build apk --release |

## 3. 架构

单层 Flutter APP，数据源适配器插件化：

- UI 层：首页（日历+列表）/ 游戏详情页 / 设置页
- 状态层：Riverpod
- 领域层：`Game` / `UpdateEvent`（类型：version_update / banner_rotation / event）/ `BannerInfo`
- 数据层：
  - `GameSourceAdapter` 接口，每游戏一个实现，统一输出 `List<UpdateEvent>`
  - 缓存仓库：Hive，公告 TTL 6h，卡池 TTL 12h，下拉强制刷新
  - 解析：JSON 接口优先，HTML 解析（html 包）兜底

新增游戏 = 新增一个 Adapter，不动主框架。

## 4. 数据源规划

| 游戏 | 来源 | 备注 |
|---|---|---|
| 原神/崩铁/绝区零/崩3 | 米游社公开接口 | JSON，含公告与资讯 |
| 明日方舟 | 官网/游戏公告 | JSON + HTML 兜底 |
| 鸣潮/战双 | 库洛官网公告 | HTML 解析为主 |
| Nikke 国服 | 官网公告 | HTML 解析 |
| 阴阳师 | 官网公告 | HTML 解析 |
| 异环 | 官网 | 预约期信息少，先占位 |

容错策略：抓取失败保留旧缓存 + Toast 提示；单源失败不影响其他游戏。

## 5. 技术选型

flutter_riverpod / hive_flutter / dio / html / table_calendar / cached_network_image / url_launcher / intl

## 6. 页面

1. **首页**：上月历视图（事件日标记，颜色区分事件类型）+ 下当日更新列表（按游戏分组卡片）
2. **详情页**：游戏主题配色 + 立绘背景；Tab：公告 / 卡池 / 活动；卡池 Tab 显示 UP 角色立绘与起止时间
3. **设置页**：游戏勾选、缓存清理、数据源状态

## 7. UI 风格（已选定）

**日间模式 = 风格 A（明亮幻想系），夜间模式 = 风格 B（深色科幻系），首页提供日夜切换按钮**。风格 C 弃用。详情页按各游戏自身配色独立设计。
