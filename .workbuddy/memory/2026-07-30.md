# 2026-07-30 工作日志

## 需求：日历按「活动开始时间」而非「公告发布日」标记
用户希望公告（如明日方舟 07-25 公告、活动 08-01 开启）在日历上标记到活动开始那天，而非发布日。

### 实现
- `models.dart`：`UpdateEvent` 新增可选 `activityDate`（活动开始时间），`date` 保留发布日；新增 `effectiveDate` getter（activityDate ?? date）。toJson/fromJson 同步。
- `sources.dart`：新增 `extractActivityDate(text, publish)` 抽取活动开始日：
  - 高置信度优先匹配 `活动时间/开放时间/开启时间：M月D日`（方舟 brief 实测结构化，如 `活动时间：08月01日 12:00 - 08月29日`）。
  - 通用候选按上下文打分（开启/开放/上线/活动/版本 +分，维护/停服 -分），取发布日之后、180 天内分最高者（同分取最早）。
  - `_resolveActivityDate` 改为「早于发布日且差距>45天才视为次年」，避免晚发公告把日期错推到下一年。
  - 所有数据源（Miyoushe/Arknights/Kuro/Yihuan 详情页/Gamekee/OfficialWeb）构造时传入 activityDate。
- `providers.dart`：`eventsByDayProvider` 改用 `effectiveDate` 分组（日历+当日列表按活动日）。
- `widgets.dart`：`EventCard` 在活动日≠发布日时显示「公告于 M月D日」小字，保留发布日上下文。

### 验证
- Python 端口对真实方舟 brief 验证：夏日嘉年华/寻访→08-01、复刻(发布07-18)→07-20、关卡(发布07-03)→07-10、跨年1月活动(发布12-20)→次年01-05，均正确。
- `flutter analyze` 0 错误（仅 tool/fetch_test.dart 开发脚本 info）。
- 构建 APK：`build/app/outputs/flutter-apk/app-release.apk`（21.7MB），未 git 提交。

### 已知局限
- 抽取是启发式的：公告未写明具体活动日、或文中多日期时可能标错/回退发布日。方舟因 brief 结构化最准；其余游戏视正文含日期情况而定。
- 日历标记改用活动日后，公告在其「发布日」当天不再显示（只在活动日开始日出现）；详情页仍按发布日倒序展示全部公告。

## 微调：活动时间段取起始日 / 模糊起始回退发布日
用户反馈两点：①阴阳师「7月22日维护后-8月11日23:59」被标到 8.11（结束日），应取起始日 7.22；②异环「1.2版本更新后~2026年…」起始无明确日期，应回退到发布日。

### 改动（仍仅在 `sources.dart` 的 `extractActivityDate`）
- 新增 `_activityRangeRe`：识别「DATE1 分隔符(-~–—至到) DATE2」区间，直接取起始日 DATE1（覆盖「7月22日维护后-8月11日」被结束日覆盖的问题）。
- 新增 `_activityVagueRe` + 守卫：若区间起始是「版本更新后/维护后/更新后/开服后/上线后/版本更新」且前面无任何日期 token（如异环），返回 null → 回退发布日。
- 通用兜底扫描改用 `_dateTokenRe`（仅 YYYY-MM-DD / M月D日，去掉 M-D，避免「07-22」误匹配）。
- 匹配顺序：标签 → 区间起始 → 模糊起始(null) → 通用打分。

### 验证
- Python 端口 9 例：阴阳师区间→07-22、异环模糊→发布日(null)、方舟带/无标签区间→08-01、YYYY区间→08-01、复刻→07-20、原神前瞻→07-31、异环带标签→08-05、维护窗口同日→08-01，全部符合预期。
